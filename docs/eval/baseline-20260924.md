## Findings

### F-024 — Inspection answers from memory and contradicts durable state

`tools: none`. Asked what exists, the front office called no tool and described an empty instance while
one project and nine agents existed. In a second run it invented a five-role roster
(`kampaku-lead`, `-frontend`, `-backend`, `-qa`, `-auditor`) that does not match the nine real agents,
three of which do not exist at all.

The durable-state block was correct — it listed `kampaku [active] lead=… repositories=4 workItems=0` —
and the reply contradicted it anyway. The block states its own precedence and tells the agent to call a
tool rather than answer from memory; nothing enforces either.

This is the [F-014](results/BOARD.md) family, which the board already describes as reconciliation
covering *creation* claims but not misstated *state*.

**Diagnosis: the failure is steering, not capability.** Two controls settled it.

| Prompt | Tool calls | Answer |
|--------|-----------|--------|
| `what exists here — projects, teams, open work?` | **none** | empty instance; then an invented five-role roster |
| `Use the list_agents tool, then tell me the exact agent slugs it returned.` | **`list_agents`** | correct and in English: the eight real platform sub-agents |

So the model can call tools on this endpoint, and it reads state correctly when it does. What it does
not do is decide, on its own, that a question about the factory's own state requires reading state.
And the language question falls with it: the same model answered an English prompt in English as soon as
it had a tool result to report, which points at the reply being generated from a weak prior rather than
from retrieved state.

That reframes the fix. F-024 is not "the endpoint cannot call tools" (F-008's shape) and not "the model
is too weak". It is that **an inventory question has no enforced route to an answer**: the durable-state
block omits the roster (F-025), and the instruction to call a tool is unenforced prose.

### F-025 — The durable-state block has no agents or teams

It lists projects, pending questions, and blockers. An operator asking "what teams exist" has no
authoritative answer inside the block, and the only remaining sources are a tool call the model may
skip, or its own memory. Both runs skipped the tool.

### F-026 — Stored provider settings silently outrank the environment

`resolveModelProviderSettings` returns `store.getBootstrapState(SETTINGS_KEY)` in preference to
`config`. The provider settings written at bootstrap therefore pin the model, and changing
`KAMPAKU_AGENT_MODEL` afterwards has no effect — verified directly:

```text
env:        KAMPAKU_AGENT_MODEL=qwen2.5:7b-instruct   → loadConfig().agentModel = qwen2.5:7b-instruct
stored:     GET /api/v1/settings/model-provider       → model: qwen2.5:14b
the turn:   mode: llm · model: qwen2.5:14b            ← the stored value won
```

An operator who changes the endpoint or model in the environment and sees no change has no signal
telling them why. This is the same shape as the `KAMPAKU_CORE_URL` surprise, and it is what
[roadmap 11](../roadmap/11-multi-provider-routing.md) § Part A means by *documented precedence*.

### F-027 — The reply language ignores the request language

Both turns answered English prompts in Thai, including a prompt that said, in its first sentence,
`Answer in English`. The front-office prompt states the rule ("conversational replies may follow the
emperor's language"); nothing verifies it, and no suite scores it.

### Observation — `bootstrap` records repository links without checking they exist

With `KAMPAKU_WORKSPACE` pointed at an empty directory, `bootstrap` recorded four `file://` repository
links whose paths did not exist, all four verified with `test -d` → no. With the documented workspace
value the same four paths do exist, so this does not affect a documented run. It is still a stored
value that was never verified, which is what principle 4 forbids. Recorded as a non-blocking row.

## Operator defects

The protocol requires the operator's own mistakes in the ledger. They cost real time here:

1. **A `pkill` pattern matched the operator's own shell.** `pkill -f "dist/cli.js serve"` killed the
   command that contained that string, so a wipe-and-restart silently half-ran and the next bootstrap
   reported "Project already exists". Recovery: verify the port is free instead of killing by pattern.
2. **Two env names for one setting.** Setting `KAMPAKU_CORE_PORT` while the repo's `.env` set
   `KAMPAKU_CORE_URL` produced a CLI that reported "Core is not running" against a Core that was
   healthy. The CLI reads the URL.
3. **An empty workspace root produced a false gap.** The first bootstrap linked non-existent
   repository paths because the workspace pointed at an empty directory, not because the product is
   broken. Corrected before being reported, by re-running with the documented value.
4. **Device-brace expansion does not run in a non-interactive shell**, so a `mkdir -p a/{b,c}` created a
   literal directory named `{b,c}`. Cosmetic, but it is a reminder that the run is scripted.

## What this run establishes

- The documented boot path works on a clean instance and a real endpoint.
- **The front door does not work.** The first promise in the battery is that a stranger can ask what
  exists and be told the truth. On an empty instance with one project and nine agents, the factory
  answered in another language, called no tool, and invented the state.

That is the honest first result of the measurement program: the bar is not close, and the suite that
every other suite depends on fails at its first prompt.
